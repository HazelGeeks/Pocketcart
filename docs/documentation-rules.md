# 문서 작성과 정리 규칙

문서 구조 확인일: 2026-10-03. 적용 범위는 이 저장소의 직접 관리하는 문서입니다.
외부 라이브러리 원본 설명과 라이선스에는 이 규칙을 적용하지 않습니다.

## 파일 위치와 이름

| 종류 | 위치와 이름 | 담을 내용 |
| --- | --- | --- |
| 프로젝트 시작 안내 | 루트 `README.md` | 실행 방법, 주요 기능, 문서 목차 링크 |
| 현재 사용하는 가이드 | `docs/<topic>.md` | 현재 코드 구조, 설정, 운영 절차 |
| 코드 탐색 안내 | `docs/code-map.md` | 기능별 진입점과 책임을 가진 파일 |
| 과거 작업 기록 | `docs/archive/YYYY-MM-DD-<topic>.md` | 해당 날짜에 관찰한 결과와 검증 범위 |
| 디렉터리 목차 | 각 디렉터리의 `README.md` | 목적과 문서 목록 |
| 스토어 제출 자료 | `store-assets/` | 심사 답변, 녹화 안내, 개인정보 답변, 이미지 |
| 함수별 실행 안내 | `supabase/functions/<name>/README.md` | 해당 함수의 인증, 입력, 배포 설정 |
| 에이전트 작업 지침 | `AGENTS.md` | 문서 규칙 링크와 적용 범위 |

파일명은 영문 소문자 `kebab-case.md`를 사용합니다. 날짜는 과거 기록에만 붙입니다.
`README.md`와 `AGENTS.md`는 예외입니다. `final`, `final-v2`, `new`, `latest` 같은
임시 상태를 이름에 넣지 않고, 기존 주제의 문서를 갱신합니다.

## 한 문서에 하나의 책임

- 새 파일을 만들기 전에 목차에서 같은 주제의 문서를 찾습니다.
- 현재 가이드는 같은 주제의 정식 문서 한 곳에서 관리합니다.
- 같은 날짜와 작업의 중간 리뷰·후속 결과는 하나의 이력으로 합칩니다.
- 과거 테스트 개수나 중간 경고를 현재 상태처럼 가이드에 옮기지 않습니다.
- 이력 문서는 `docs/archive/README.md`에 등록합니다. 현재 가이드는
  `docs/README.md`에 등록하고 서로 필요한 부분만 링크합니다.
- 역할이 바뀌거나 파일을 옮기면 링크, 스크립트의 경로, 관련 목차를 함께 수정합니다.

## 내용과 검증 기준

H1 제목은 하나만 사용합니다. 첫 문단에서 문서의 목적과 적용 범위를 설명하고,
설정·작업 순서·검증을 독자가 따라갈 수 있는 순서로 씁니다.
기술 가이드는 기존 영문 문체를 유지할 수 있고, 팀 안내는 한국어로 작성할 수 있습니다.

변하는 값은 `package.json`, `app.json`, `eas.json`, migration 등 원본을 링크합니다.
버전·빌드 번호·배포 ID를 복사해야 하는 이력에는 관찰 날짜와 근거를 적습니다.
계정·시크릿·토큰·개인정보를 문서나 예제에 저장하지 않습니다.

완료 상태는 실행한 검증만 기준으로 표시합니다. 로컬 검사, 번들 생성, 서명된 빌드,
실기기 확인, 운영 DB, CI, 배포, 스토어 심사는 구분합니다. 가이드가 존재한다는
이유로 운영 적용이 완료됐다고 쓰지 않습니다. 외부 상태를 확인하지 않았다면 명시합니다.

일반 Markdown 링크는 저장소의 상대 경로를 사용합니다. 명령은 코드 블록에 넣고,
운영 데이터를 수정하는 명령에는 대상과 필요한 사전 조건을 설명합니다.

현재 가이드의 권장 구성:

```markdown
# 주제

목적과 적용 범위. 코드 확인일: YYYY-MM-DD.
운영·외부 설정 확인 여부는 별도로 기록한다.

## 현재 동작
## 설정 또는 작업 순서
## 검증 방법과 한계
## 관련 코드와 문서
```

## 안전한 삭제 기준

소스는 웹·네이티브 진입점과 플랫폼 변형, 동적 import, 테스트, 도구에서의 사용을
확인합니다. 에셋은 직접 참조뿐 아니라 Expo 설정, HTML 경로, 네이티브 리소스,
배포용 파일 복사도 확인합니다. 앱 import가 없다는 이유만으로 삭제하지 않습니다.

설정 파일, migration, 운영 스크립트, 제출 자료, 로컬 환경·자격증명은 일반적인
미사용 파일 정리 대상에서 제외합니다. 보안 포크의 소스·설치 아카이브·라이선스는
설치와 무결성 검증에 필요합니다.

중복 문서는 필요한 근거와 미완료 사항을 정식 문서에 합친 뒤 삭제합니다.
배포·DB·심사 이력은 날짜가 오래됐다는 이유만으로 삭제하지 않습니다.
정리 후에는 삭제된 파일의 남은 참조, 내부 링크, 관련 빌드 검사와 diff를 확인합니다.
재생성 가능한 출력만 지우며 실행 중인 개발 환경의 캐시를 일괄 삭제하지 않습니다.
