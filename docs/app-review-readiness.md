# App Store 재심사 준비

사용자가 전달한 카메라 권한 안내와 외부 후원 결제 반려 사유를 코드·연결된 웹
페이지·스토어 자료와 대조한 결과입니다. 코드 및 공개 지원 페이지 확인일:
2026-10-03. Apple TestFlight의 1.0.0 (21) 처리 완료·내부 테스트 상태를 조회했습니다.
App Store 재심사에 선택한 빌드와 제출 상태는 변경하지 않았습니다.

## 확인한 원인과 수정

| 항목 | 확인한 원인 | 현재 코드 변경 |
| --- | --- | --- |
| 5.1.1(iv) 카메라 | ReceiptCamera와 보존된 FoodScanPanel에 `Allow camera` 버튼 | `Continue`와 중립적 사용 목적 안내. 거부 후 설정 안내, 수동 영수증 입력 유지 |
| 유사 권한 안내 | Onboarding의 `Allow Notifications`, `Share current location` | `Continue`와 실제 시스템 창이 열리는 조건을 설명 |
| 3.1.1 후원 | Account 후원 버튼에서 Ko-fi로 이동 | 후원 컴포넌트와 전용 URL 상수 제거 |
| 간접 결제 이동 | Help & Support 페이지에도 Ko-fi 결제 링크 | 웹 지원 페이지를 계정·권한·개인정보·삭제 안내로 변경하고 후원 카드 제거 |
| 스토어 문구 | 설명·Notes·답변에 “기능을 해제하지 않는 선택적 Ko-fi 지원” | 해당 문구 제거. 수정 빌드 기준 답변 템플릿 준비 |
| 개인정보 일치 | 중단된 Food Scan을 현재 수집 기능으로 설명, Ko-fi 제공자 언급 | 현재 중단 상태와 과거 요청 보존 범위를 구분하고 후원 문구 제거 |

영수증 카메라는 사용자 행동 전 권한 요청을 하지 않습니다. 요청 버튼을 눌렀을
때 시스템 창을 열며, 영구 거부 상태에서는 설정으로 연결합니다. 설정에서 앱으로
돌아오면 권한을 다시 조회합니다. Expo 설정·camera plugin·네이티브 Info.plist의
카메라 설명은 현재 제공하는 영수증 촬영과 수동 입력 대안으로 동일하게 맞췄습니다.
Food Scan은 서버·앱에서 계속 중단 상태입니다.

Apple의 [권한 안내](https://developer.apple.com/design/human-interface-guidelines/privacy/)는
사전 안내의 동작을 `Continue` 또는 `Next`처럼 표현하도록 설명합니다.
[3.1.1 결제 지침](https://developer.apple.com/app-store/review/guidelines/#in-app-purchase)은
개발자 팁에 IAP를 사용할 수 있다고 안내합니다. 이번 반려는 사용자가 전달한
실제 심사 판단이므로 “선택적 후원이고 기능을 해제하지 않는다”는 문구로 해결했다고
판단하지 않습니다. 현재 앱에서는 후원을 제거했습니다. 향후 도입한다면 StoreKit/IAP
상품, 실제 결제 검증, 심사 자료까지 별도로 구현해야 합니다.

## 재제출 전에 남은 확인

1. **운영 웹 배포**: 2026-10-03에 수정한 웹을 Cloudflare에 배포했습니다. 버전은
   `baa63231-e353-4d1f-9e01-bf91ec7c013e`이며 운영 entry JavaScript에
   `ko-fi.com`이 없는 것을 확인했습니다. 실제 지원 페이지에서도 후원 카드가
   제거됐습니다. 지원·Privacy·Terms·계정 삭제 URL은 HTTP 200입니다. 배포 근거는
   [QA 기록](../store-assets/app-review/physical-device-qa.md)에 남깁니다.
2. **정확한 제출 빌드**: 2026-10-03에 커밋 `a3e425a25fac54dc032f373296099027ce468122`로
   App Store 배포 서명한 1.0.0 (21)을 로컬에서 빌드하고 TestFlight에 업로드했습니다.
   Apple build ID는 `5e575bc5-9ecc-439d-819a-ca1e15aca993`이며 `VALID`,
   `IN_BETA_TESTING`과 기존 내부 `Group` 배정, en-US 테스트 안내 저장을 확인했습니다.
   외부 테스트 상태는 `READY_FOR_BETA_SUBMISSION`입니다. 실기기 QA의 개발 서명
   바이너리와 배포 서명 IPA는 별도 아티팩트입니다. 심사 빌드 선택·재제출은 남아 있습니다.
   제출 명령과 workflow는 명시한 EAS build ID 또는 실제 artifact 경로를 요구합니다.
3. **실기기 권한·촬영 검사**: Device Hub 화면 공유 중에는 PocketCart와 기본
   카메라 모두 검은 화면이었습니다. 공유를 끈 뒤 사용자가 두 앱의 영상 정상화를
   확인했습니다. 최종 빌드 21에서도 사용자가 직접 영상과 촬영된 사진의 정상
   표시를 확인했습니다. 이 결과를 카메라 코드 수정의 효과라고 설명하지 않습니다.
   거부 안내·설정 이동·수동 입력,
   권한 ON 복원은 확인했습니다. 최초 Continue → 시스템 창과 OpenAI 전송
   동의·추출·사진 저장 정리는 별도 검증이 필요합니다. 위치·알림 거부 흐름도 별도로 확인합니다.
4. **문안·촬영 증거**: [답변 원본](../store-assets/app-review/response-draft.txt)의
   영상·빌드·기기·데이터 출처·권리 근거 입력란을 채우고 Notes의 4,000자 한도를
   재확인합니다. 이전 빌드 18 QA 기록은 새 빌드 QA로 재사용하지 않습니다.
   [촬영 순서](../store-assets/app-review/recording-checklist-ko.md)를 따릅니다.
5. **스토어·외부 설정**: 개인정보 설문은 영수증의 계정 연결 사진 수집이 남으므로
   Photos or Videos를 일괄 제거하지 않습니다. 실제 로그인·계정 삭제·사진 정리,
   전용 일반 심사 계정, 선택한 빌드의 screenshots와 등록 문구를 확인합니다.
   기존 구독 Restore/Manage는 유지했습니다. 활성 구독·등록 IAP의 실제 상태를
   확인해 새 판매 기능이 없는 이유와 기존 사용자 처리도 사실대로 설명합니다.
6. **지원 연락 경로**: 현재 지원 페이지는 안내 페이지입니다. 일반 문의용 이메일이나
   문의 폼은 확인되지 않았습니다. 계정 삭제 폼을 일반 문의 접수로 안내하지 말고,
   실제 운영하는 문의 수신 경로를 지정한 뒤 페이지와 심사 연락 정보를 맞춥니다.

새로운 심사 지적이라고 단정한 항목은 위의 두 반려 사유뿐입니다. 나머지는 코드와
자료에서 확인한 제출 준비 사항이며 Apple의 추가 반려를 예측하거나 승인을 보장하지
않습니다.

## 검증과 배포 범위

`npm run release:native:check`의 typecheck·lint·테스트·웹 export·설정·스토어
자료 검사를 통과했습니다. 추가한 카메라 동작 검사는 최초 요청 전 미요청, Continue
호출, 수동 입력 복귀, 영구 거부의 Settings 동작, 앱 복귀 시 조회, 허용 상태를 검증합니다.
release 검사에는 사전 안내 버튼 문구, 후원 경로 잔존 여부, 카메라 설명 동기화 확인을
추가했습니다. 기본 에셋 검사 통과는 screenshots나 심사 답변 완성 여부를 증명하지 않습니다.

개발 서명한 최신 iOS 빌드의 컴파일·서명 검증·실기기 설치와 실행을 확인했습니다.
실제 기기에서 확인한 동작과 미검증 항목은
[날짜별 QA 기록](../store-assets/app-review/physical-device-qa.md)을 기준으로 합니다.
운영 웹 배포와 지원 페이지 확인을 완료했습니다. 현재 작업을 main에 커밋·푸시하고
463개 테스트를 포함한 로컬 release 검사, 보안 검사(전체 심각도 0건), GitHub CI와
Cloudflare 배포 검사를 통과했습니다. TestFlight 빌드 21의 내부 테스트 가능 상태와
테스트 안내 저장은 확인했습니다. App Store 심사 Notes 수정·빌드 선택·재심사 제출은
수행하지 않았으며, 사용자의 TestFlight 앱 업데이트·설치는 별도 확인이 필요합니다. 자세한 명령은
[모바일 배포 가이드](mobile-store-release.md)를 참조합니다.
